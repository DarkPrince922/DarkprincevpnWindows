# DarkPrince VPN — Windows

Клиент к той же связке, что и мобильные версии: панель **Remnawave** и кабинет
**Bedolaga**. Работает в двух режимах — системный прокси и TUN.

В репозитории две сборки. Рабочая — **`app-tauri/`**: движок на Rust
(`app-tauri/engine`, проверяется тестами на любой машине), оболочка на Tauri и
интерфейс на обычных HTML и CSS. Старая версия на WPF лежит в `src/` и описана
ниже — от неё остались разбор подписки и работа с системой, переехавшие в
движок один в один.

## Два режима

| | Системный прокси | TUN |
|---|---|---|
| Права администратора | не нужны | **нужны** |
| Браузеры | да | да |
| Программы со своим сетевым стеком (игры, торренты) | нет | да |
| Как работает | Xray слушает HTTP на 127.0.0.1:10809, адрес прописывается в настройки интернета Windows | виртуальный адаптер Wintun забирает весь трафик и отдаёт его в SOCKS ядра |

Режим прокси проще и безопаснее: он ничего не меняет в системе, кроме одной
ветки реестра текущего пользователя. Режим TUN перехватывает всё, но правит
таблицу маршрутов.

## Как устроено

```
       режим прокси                        режим TUN
  настройки Windows                   адаптер Wintun
          │                                  │
          ▼                                  ▼
   HTTP 127.0.0.1:10809            tun2socks ──► SOCKS 127.0.0.1:10808
          └──────────────► Xray-core ◄─────────────────┘
```

Ядро — обычный `xray.exe` рядом с приложением, отдельным процессом. Оно ест
**тот же JSON-конфиг, что отдаёт панель**, поэтому роутинг, правила и
балансировщики сохраняются: приложение подменяет в конфиге только `inbounds`.

### Про зацикливание трафика

Главная тонкость режима TUN. Xray ходит к серверу через обычную сеть, и если
весь трафик уйдёт в туннель, ядро начнёт слать пакеты в собственный туннель.
Поэтому перед поднятием туннеля приложение:

1. находит основной шлюз системы;
2. достаёт из конфига адреса **всех** серверов (в конфиге с балансировщиком их
   несколько) и разрешает их в IP, пока DNS ещё прямой;
3. прокладывает до каждого отдельный маршрут через физический шлюз;
4. и только потом направляет остальной трафик в туннель — двумя половинками
   `0.0.0.0/1` и `128.0.0.0/1`, чтобы не трогать исходный маршрут по умолчанию
   и не восстанавливать его потом.

Если маршрут до сервера проложить не удалось, приложение не поднимает туннель:
лучше отказ, чем оборванная сеть.

### Про отзывчивость и завершение

Всё, из чего состоит подключение, — блокирующее: запуск процессов, разрешение
имён, вызовы `route` и `netsh`, ожидание появления адаптера. В режиме TUN это
складывается в несколько секунд, поэтому подключение и отключение уходят на
фоновый поток: на потоке интерфейса окно превращалось бы в белый прямоугольник
«программа не отвечает». Режим прокси просто был достаточно быстрым, чтобы это
не бросалось в глаза.

Ядро и мост — отдельные процессы, и при аварийном завершении приложения они
остались бы работать. Штатный выход снимает их сам; кроме того, приложение
подчищает забытые процессы при следующем старте. Ищет оно их **по полному пути
к файлу**, а не по имени: `xray.exe` есть у половины VPN-клиентов, и чужой
процесс — не наша собственность. В старой версии на WPF ту же задачу решал
объект задания Windows с флагом `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`.

Следы прошлого запуска (наши половинки маршрута по умолчанию и осиротевший
мост) приложение вычищает при старте: пока они на месте, трафик уходит в
несуществующий туннель и сеть выглядит мёртвой.

### Про порты

Привычные порты ядра (10808 и 10809) может занять другой VPN-клиент. Снимать
за это чужой процесс приложение не станет — это не его собственность. Вместо
этого на каждое подключение порты выбираются заново: сначала пробуются
привычные, а если заняты — система выдаёт любые свободные. Выбранные порты и
попадают в конфиг ядра, в настройки прокси и в мост.

## Окно, трей и выход

Три разных действия, которые легко перепутать, поэтому они разведены явно:

* **Свернуть** — обычное сворачивание. Кнопка остаётся на панели задач, значок
  — в трее.
* **Крестик** — задаёт вопрос: свернуть в трей или выйти совсем. Раньше он
  молча прятал окно, и это сбивало с толку: человек «закрывал» приложение,
  запускал снова — и значков в трее становилось два.
* **Выход** (в вопросе или в меню значка) — снимает соединение, возвращает
  системный прокси, убивает своё ядро и мост, освобождает порты и только потом
  закрывается.

Приложение пускает себя в одном экземпляре: повторный запуск не поднимает
второе приложение, а показывает работающее. Без этого значки в трее копились
по числу запусков — приложение живёт с закрытым окном, а ярлык об этом не
знает.

Отдельная тонкость — режим «весь трафик»: он требует прав администратора, и
приложение перезапускает себя повышенным. Windows не пропускает сообщения от
обычного процесса к повышенному, поэтому приложение явно разрешает своему окну
принимать то единственное сообщение, которым второй запуск говорит первому
«покажись». Иначе ярлык перестал бы открывать уже работающее приложение.

## Сборка

Рабочая версия — Tauri. Нужны Rust и Node:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/fetch-cores.ps1 -OutputDirectory app-tauri/src-tauri/core
cd app-tauri/src-tauri
npx @tauri-apps/cli@^2 build
```

Установщик появится в `app-tauri/src-tauri/target/release/bundle/nsis/`. Тесты
движка идут отдельно и не требуют Windows:

```
cd app-tauri/engine && cargo test
```

Папка `core/` с `xray.exe`, `tun2socks.exe`, `wintun.dll` и базами
geoip/geosite в репозитории не хранится — вместе они весят под сотню мегабайт
и обновляются независимо от приложения.

Собранный установщик можно забрать из артефактов сборки на CI.

```
  Core/

  Data/

    SubscriptionRepository.cs  подписки, тарифы, устройства

    XrayProcess.cs         запуск и остановка ядра

```

## Если приложение не запускается

Приложение пишет журнал в `%APPDATA%\DarkPrinceVPN\app.log` — первая же
строка появляется там при старте, до создания окна. Отсюда два случая:

* **в журнале есть свежая запись о запуске** — процесс стартовал, и дальше в
  журнале лежит текст ошибки; то же сообщение показывается в окне;
* **записи нет вовсе** — процесс не дошёл даже до этого. Обычно это
  антивирус (самораспаковывающийся exe рядом с `xray.exe` — частое ложное
  срабатывание), заблокированный после скачивания файл (свойства файла →
  «Разблокировать») или неполностью скачанный архив.

Второй экземпляр приложения не запускается: вместо него показывается уже
работающее. Если ни окна, ни значка в трее нет, а запуск ничего не открывает —
снимите задачу `DarkPrince VPN` в диспетчере задач.

## Чего пока нет

* автозапуска вместе с системой;
* подписи установщика (Windows будет показывать предупреждение SmartScreen).
