# DarkPrince VPN — Windows

Клиент к той же связке, что и мобильные версии: панель **Remnawave** и кабинет
**Bedolaga**. Работает в двух режимах — системный прокси и TUN.

> **Статус: первая версия движка.** Собирается на CI, но на живой Windows ещё
> не запускалась. Сейчас подписка загружается по ссылке — вход через кабинет
> (Telegram и почта), тарифы и баланс будут следующим шагом.

## Два режима

| | Системный прокси | TUN |
|---|---|---|
| Права администратора | не нужны | **нужны** |
| Браузеры | да | да |
| Программы со своим сетевым стеком (игры, торренты) | нет | да |
| Как работает | Xray слушает HTTP на 127.0.0.1:10809, адрес прописывается в настройки интернета Windows | виртуальный адаптер Wintun забирает весь трафик и отдаёт его в SOCKS ядра |

Режим прокси проще и безопаснее: он ничего не меняет в системе, кроме одной
ветки реестра текущего пользователя. Режим TUN перехватывает всё, но правит
таблицу маршрутов.

## Как устроено

```
       режим прокси                        режим TUN
  настройки Windows                   адаптер Wintun
          │                                  │
          ▼                                  ▼
   HTTP 127.0.0.1:10809            tun2socks ──► SOCKS 127.0.0.1:10808
          └──────────────► Xray-core ◄─────────────────┘
```

Ядро — обычный `xray.exe` рядом с приложением, отдельным процессом. Оно ест
**тот же JSON-конфиг, что отдаёт панель**, поэтому роутинг, правила и
балансировщики сохраняются: приложение подменяет в конфиге только `inbounds`.

### Про зацикливание трафика

Главная тонкость режима TUN. Xray ходит к серверу через обычную сеть, и если
весь трафик уйдёт в туннель, ядро начнёт слать пакеты в собственный туннель.
Поэтому перед поднятием туннеля приложение:

1. находит основной шлюз системы;
2. достаёт из конфига адреса **всех** серверов (в конфиге с балансировщиком их
   несколько) и разрешает их в IP, пока DNS ещё прямой;
3. прокладывает до каждого отдельный маршрут через физический шлюз;
4. и только потом направляет остальной трафик в туннель — двумя половинками
   `0.0.0.0/1` и `128.0.0.0/1`, чтобы не трогать исходный маршрут по умолчанию
   и не восстанавливать его потом.

Если маршрут до сервера проложить не удалось, приложение не поднимает туннель:
лучше отказ, чем оборванная сеть.

### Про отзывчивость и завершение

Всё, из чего состоит подключение, — блокирующее: запуск процессов, разрешение
имён, вызовы `route` и `netsh`, ожидание появления адаптера. В режиме TUN это
складывается в несколько секунд, поэтому подключение и отключение уходят на
фоновый поток: на потоке интерфейса окно превращалось бы в белый прямоугольник
«программа не отвечает». Режим прокси просто был достаточно быстрым, чтобы это
не бросалось в глаза.

Ядро и мост — отдельные процессы, и при аварийном завершении приложения они
оставались бы работать. Оба привязываются к объекту задания Windows с флагом
`JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`: как только исчезает приложение — штатно,
снятое через диспетчер задач или упавшее — система убивает их сама. Закрытие
окна прячет его сразу, а снятие туннеля идёт фоном и ограничено по времени,
чтобы задача не осталась висеть в диспетчере.

Следы прошлого запуска (наши половинки маршрута по умолчанию и осиротевший
мост) приложение вычищает при старте: пока они на месте, трафик уходит в
несуществующий туннель и сеть выглядит мёртвой.

## Сборка

Нужен .NET 8 SDK.

```powershell
dotnet publish src/DarkPrinceVpn/DarkPrinceVpn.csproj -c Release -o publish
powershell -ExecutionPolicy Bypass -File scripts/fetch-cores.ps1 -OutputDirectory publish/core
```

Готовая сборка лежит в `publish/`: `DarkPrinceVPN.exe` и папка `core/` с
`xray.exe`, `tun2socks.exe`, `wintun.dll` и базами geoip/geosite. Эти файлы в
репозитории не хранятся — вместе они весят под сотню мегабайт и обновляются
независимо от приложения.

Собранный архив можно забрать из артефактов сборки на CI.

## Структура

```
src/DarkPrinceVpn/
  Core/
    ProxyProfile.cs        модель узла подписки
    LinkParser.cs          разбор подписки: Xray JSON, base64, ссылки
    XrayConfigBuilder.cs   сборка конфига ядра
  Data/
    ApiClient.cs           запросы к кабинету и обновление токена
    AuthRepository.cs      вход через Telegram и почту, регистрация
    SubscriptionRepository.cs  подписки, тарифы, устройства
    AppStore.cs            настройки и токены (шифруются DPAPI)
  Vpn/
    XrayProcess.cs         запуск и остановка ядра
    SystemProxy.cs         режим прокси: настройки интернета Windows
    TunManager.cs          режим TUN: адаптер, маршруты, мост
    ChildProcessJob.cs     потомки не переживают приложение
    VpnController.cs       общий выключатель
  MainWindow.xaml          интерфейс
```
